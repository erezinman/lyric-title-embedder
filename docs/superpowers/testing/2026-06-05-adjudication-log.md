# Interaction-Audit Adjudication Log

Every audit-test failure gets a verdict here BEFORE any fix. Verdicts:
- **CODE-BUG** — the test encodes desired behavior; the code changes, the test stands.
- **TEST-BUG** — the test misencodes desired behavior; the test changes, with a spec citation.
- **SPEC-GAP** — genuinely ambiguous; escalated to the user before fixing.

Authoritative references: docs/superpowers/specs/*.md, design-system/HANDOFF_finish-ui-answers.md,
engine semantics (engine/), CLAUDE.md.

## SPEC-GAP questions

**SPEC-GAP — ADJ-09 (ExportMenu double-click Burn guard).** A fast double-click on **Burn video** currently fires `onBurn` twice (two burn jobs) because the only safeguard is the popover unmounting on `onClose()`. Should we:
- **(A)** Add an explicit one-shot guard — disable the Burn button immediately on first click (mirroring the `busy`/disabled pattern already used in CreateProjectModal) so a second click is impossible regardless of unmount timing. **[Recommended]** — burn launches a heavyweight ffmpeg job; a duplicate is wasteful and confusing, and the guard is cheap and consistent with the existing modal pattern.
- **(B)** Leave it as-is and rely on `onClose()` unmounting the popover before a second click can land (the designer's stated single-surface, closes-on-Burn behavior, HANDOFF §4c).

Recommendation: **A**.
