B1

Timeline structure — flat track vs. per-event lanes

The triage called this “the single biggest divergence.” Same data, same time scale, both rendered live below.

Kit One flat track — blocks positioned by time only .track · 36px · single row
→
Compact & honest for sequential cues. But blocks share one row, so the overlapping chorus lines collide and occlude each other (hatched zone) — and there is no room for per-cue animation strips, the feature the port adds. No event labels.
Port One labelled lane per event + anim strips Recommend — with tweaks .wt-lane · 30px · 124px gutter
→
Overlap resolves cleanly — the echo line gets its own row. Vertical room for animation strips (cyan = fade, amber = pop) which the flat track can't host, plus scannable event labels. Costs a 124px label gutter and grows tall on long songs.
▍ Verdict

Ship the lane model — but understand why. It isn't really about overlap (most songs are sequential); it's that the port's per-cue animation strips need vertical room a 36px flat row can't give. That's a legitimate port-ahead the kit never depicted. Two tweaks I'd ask for before sign-off:

1 · Trim the gutter. --tl-gutter: 124px is heavy on a 252px dock — target ~88px with truncation, or make it collapsible.
2 · Open question: auto-flatten events that have no animations and don't overlap, to cut vertical scrolling on long lyrics? Or keep one-lane-per-event always for predictability?

B2

Waveform — placeholder bars vs. honest tick ruler

The engine has no audio source. The question is whether to draw a waveform anyway.

Kit 56 placeholder bars + fixed 6-mark ruler .wave · .bar.on = grad-brand
→
Looks like a real editor — but the bar heights are random noise, not audio. It implies amplitude data we don't have. The kit itself tags these “placeholder.”
Port Honest adaptive tick ruler — no fake bars Recommend .ruler-track · tickStep(dur)
→
Truthful. A scrubbable time axis with adaptive ticks (scales with zoom), a draggable playhead with a grab-head, and no invented data. Reads as deliberate, not unfinished.
▍ Verdict

Keep the honest tick ruler. Painting amplitude bars over audio we never decoded is misleading data-viz — and the kit literally labels them a placeholder. The tick ruler is the more confident, more professional read.

Revisit only when real audio lands (the daemon could decode the attached video's track) — at that point bars become honest and we render them for real.
